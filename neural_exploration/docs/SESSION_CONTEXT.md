- **（M11-R40）判据之间禁止连带降级（no verdict contagion）**：一个判据的判定**只能**由**它自己作用域内**的证据决定；其他判据的输入不可得，**不得**用作下调本判据的理由 —— 正确做法是**把不可得的那一项单列成行、各判其四态**。（与"判据名必须与实测范围一致"是同一枚硬币的两面：**既不夸大、也不缩小**。实例：DQ-4 受阻不得下拽 P2 的 `pass`。）
- **（M11-R40）吞吐必须当场实测，不得按锚外推**：实测同小时吞吐波动可达 **20×（1.6 ↔ 32 KB/s）** ⇒ 取数决策须有当场实测吞吐支撑（`data/m11_throughput_measured.csv` + 断言 P1.17c）。
- **（M11-R40）对"个数/长度"量也要恒等式验算**：`np.triu_indices` 返回 `(row,col)` 元组 ⇒ 曾把配对数报成 2（实际 6）⇒ **计数与值个数必须交叉核对**（与量纲自检同族）。


- **（M11-R45）`ms/step` 不是单一量**：必须写全**三元组「投递口径（step/chunk）× 事件率 × 档位 N」**；**档因子与口径因子不得相乘外推**；**步数必须含 settle**（`settle/dt + T/dt`，短 T 的定价误差最大）。本工作包已连续三次错在"未写全口径的单一数字"（R34 解释器 / R43 口径 / R45 settle+事件率）——**同一家族错误的第三次实例化，升为通用纪律**。
- **（M11-R45）预算必须以实测为准，且预注册"事后不得择口径"**：M11 G1 预算已三次被实测击穿（§9.2 `8.87` → R36 `16.9` → R45 `51.9`）。凡在**未实测因子**上押注的预算不得当结论；裁决规则必须**在出数之前预注册**（本次：E 段孪生臂逐位 ⇒ 用 B 案 chunk 生产；否则 ⇒ A 案正式提高包络并 append-only 改写上限）。


- **（M11-R46）凡登记进 `final=1` 参数表的公式，必须附"可执行验算算例"**：失效点常在"文档化公式"而非计算代码——**"文档与实现分叉"是一类独立失效模式**（实现对了、登记错了，读者照错的算）。**修正后仍须做影响面审计**：因为"缺陷存在"与"缺陷生效"是两件事（前者登记，后者须实测排除）。
- **（M11-R46）指令边界按"意图＋不得越界"双重解释**：本次意图是"不得改他节点文件、不得改已判定产物"；若"只改 X"的字面读法**会使修正失效**，则**执行意图并把偏离显式报请确认**（优于机械服从字面）。


- **（M11-R48）先冻结工具、后运行**：凡产生"被判据采信"的产物之前，必须先记录工具（含依赖）的 `sha256`；工具一旦改动，该臂集**必须重跑**，或**显式标注为"混合来源（mixed provenance）"**并说明改动内容与是否影响数值。**能事后变的量必须先定死**（与"判据预注册"同族）。


- **（M11-R50）τ 不可单报**：`dτ/τ = dφ/(φ·ln φ)` ⇒ **φ≈0.97 处 1% 的 φ 误差 ⇒ ≈19% 的 τ 误差**。**τ 必须与 φ、时间基、平滑约定同时报出**；**"只比 τ"的交叉核对没有意义**（τ 的差异先归因到口径维度，再谈一致或不一致）。
- **（M11-R50）交叉核对应穷举口径组合并逐格归因**：不一致的格子必须定位到**具体口径维度**（箱宽/平滑/代理/状态分辨率）；**归因是对一致性的加强，不是对不一致的掩盖**。8 格穷举中一致格达 0.001–0.007% 时，可以说"两个独立实现一致"。


- **（M11-R53）端到端成本必须给"两个量"**：报成本时**必须同时给出「仿真循环 `wall_s`」与「进程总墙钟」**，只给其一即为口径不全（与"ms/step 三元组"同族）。实测教训：生产者自报 `wall_s` 13.4/19.2 min，而**进程真实墙钟 95.3/107.5 min**（差额 **82–88 min/臂**，是"每臂一次"而非一次性）⇒ 86 臂矩阵 ≈**129 wall-h** ⇒ 原 G1 方案不可行。
- **（M11-R53）"先探针后裁决"必须包含"跑一个真实臂并量其端到端墙钟"**：单臂定价若只在极短时长（如 T=1 s）测过，固定开销会被掩盖而未被识别。


- **（M11-R55）「MPS 串行」≠「主机侧串行」**：重资源作业（**>1 GB RSS 或 MPS**）必须**整机独占** —— 运行期间其它节点不得并发跑同量级网络（31k 档 RSS ≈1.2 GB/臂）。**调度单位是"整机"而非"设备"**。（M10 的"并发使 ms/step 2.4→14.1"是设备侧证据，本条是主机侧对偶。）
- **（M11-R55）未解释的墙钟差必须重述为可伪证假设**：当"自有分段合计"远小于"进程生命周期"（实测 19.8 min vs 107.5 min ⇒ ≈88 min 未执行我们的代码）时，问题不是"开销在哪一段"而是"进程在等什么"；须给出**带预注册判据的假设**（本轮：臂 3 若 ≈25–35 min ⇒ 竞态性成立、修法是调度；若仍 ≈90–110 min ⇒ 稳定系统级异常）。


- **（M11-R56）"吞吐受限 ⇒ unavailable"的判决带时效**：实测同对象吞吐可在数小时内摆动 **3,600×（1.6 KB/s ↔ 5.9 MB/s）** ⇒ 该判决的对偶是 **"此刻不可行" ≠ "永久不可行"**。凡以吞吐为由的 `unavailable`，必须登记**判决时刻 + 当时实测吞吐**，并注明**须以当场探针复核后方可作为取数依据**（复核周期 ≤24 h 或每次调度决策前）。
- **（M11-R56）完整性判据优先用"服务端锚定"**：S3 多段对象 `ETag = md5(concat(md5(part_i))) + "-N"` 可复算 ⇒ **他证强于 sha256 的自洽**（后者只证"我算两次一样"）。两者并列而非替代；sha256 仍须标注基准（`file_bytes`/`payload`/`semantic`）。
- **（M11-R56）"够用"必须实测，不得推断**：主agent 曾推断"`channels.csv` 1 MB 前缀够用"，实测覆盖率 **0%**（前缀 id 849,705,558–849,800,796 vs 引用 849,990,690–850,264,442）。
- **（M11-R56）口径含刺激期时，只能作"显式标注的上界"**：`units.csv::firing_rate` 全量 `epoch_name_quality_metrics=complete_session`（含视觉刺激期）⇒ (a) 自发率带仍 `unavailable（口径不含）`；该率只可作**命名显式**的上界候选行，**不得冒充带**。

## 〇、本阶段最重要的三条方法学纪律（M9/M10 付学费换来的，务必先读）

1. **数值可信度三律**：① **口径一致才可比**（跨脚本/跨入口比较绝对量前，必须核对**测量窗口径 + 初值语义**）；
   ② **可复现 ≠ 正确**（M9 冻结引擎的 4.6783 Hz 可复现到 2.6e-6，但修好投递公式后是 **3.5225 Hz/−24.7%**）；
   ③ **同一量的两个独立估计器必须断言一致**（若工具里有两个估计器而没人断言二者相等，那它就是"埋着的 bug 检测器"）。
2. **判据必须可证伪且统计可判**：构造上必然失败（或必然通过）的判据不是判据；**样本量不足 ⇒ 判 `invalid`**（四态：`pass`/`fail`/`invalid`/`unavailable`，未测 ≠ 未命中）。
3. **机制级阴性结论的三层前置断言**：① 接线（读回断言）② 实现（引擎内确有该状态变量动力学）③ **动态范围**（`std` 落量级门，**仅 >0 不够**）。

**算力纪律**：**MPS 作业严格串行**（并发实测 `ms/step` 2.4→14.1，**6× 退化**）；**CPU 作业设 `OMP_NUM_THREADS=1`**（未限线程实测 4–5× 退化）；**>10 min 的作业由主agent 以托管后台作业启动**（子agent 回合结束时其长作业会被回收；同机托管作业已实测稳定跑 800–3300 s）。
🔴 **判断长作业进度必须看"累计 CPU 时间 / 墙钟"之比，不能看 `ps` 的 `%CPU`**——macOS 的 `%CPU` 是**近期采样**；实测 4 个托管作业 51 分钟累计 CPU 仅 **4:35**（占空比 ≈10%，后台 QoS 饥饿），单臂墙钟 2102 s 而纯计算只需 213 s。**该比值 ≪1 ⇒ 先怀疑调度饥饿，不要误判为"代码慢"或"死锁"，更不要贸然 kill**（L46）。

**机制实验的阳性对照硬条款（D1 家族第 4 次复现后升级为协议）**：任何"机制 X 有效/无效"的结论，必须先在**只有该机制能起作用的最小实验**里证明**开/关可测地不同**——① **作用域断言**（读码/读回：该参数出现在哪个表达式里）+ ② **最小阳性对照**（断言逐位不同；否则判 `MECHANISM_NOT_IMPLEMENTED`）。反例：M10 的 M-4 调质增益 `mod_scale` **只乘外部事件幅度**（`larval_zf_engine.py` L382/L403），λ×0 臂里 M0/M-1/M-4 群体轨迹 **sha256 完全相同**。

## 四、关键技术约定（踩坑记录，执行节点必读）

1. **Brian2 Im 为"内向正"约定**——用"外向正"写法会导致发散（M1 实测踩坑）
2. **NEURON 温度必须 6.3°C**（Q10 缩放，否则波形偏差）
3. **HH 静息瞬态漂移污染 PSP 基线**——用本地基线（非全局基线）解决
4. **HH 神经元统一加 refractory=2ms**（否则每个时间步都发尖峰）
5. **Brian2 多隔室**：SpatialNeuron/Soma/Cylinder 可用（M1 已验证）
6. **NEURON 点过程电流按 nA 注入**：mod 里 i (pA) 无单位换算会放大 1000×（M2 踩坑，NMDA 假性发放）
7. **NEURON Python 点过程会被 GC 回收**：需保留引用，否则 50Hz 训练只剩最后一脉冲（M2）
8. **Brian2 编译缓存**：TimedArray 形状/名字与 Synapses 参数进入代码串，变化触发 80–120s 重编译——固定形状+显式命名+namespace 传参（M2，也修复了 M1 同类问题）
9. **NEURON 9.0.1 不支持经典 gap.mod 的 EXTERNAL vother**——缝隙连接参考改用 scipy solve_ivp 独立解（M2）
10. **M3 注意**：反射弧多神经元链复用 ChemicalSynapse/GapJunction，注意突触前触发事件与多隔室耦合
