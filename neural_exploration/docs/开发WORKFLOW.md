## 二、角色分工（铁则）

| 角色 | 职责 | 禁止 |
|---|---|---|
| **主 agent（本节点）** | ① 调度：按依赖图决定"现在推进哪个里程碑"；② 产出 workflow 与里程碑启动指令；③ **验收**：复跑测试、核对 Pass 标准、查验产物文件真实性、检查回归；④ 批准进入下一里程碑；⑤ git 提交与 SESSION_CONTEXT 更新 | 不亲自写实现代码、不亲自跑业务验证脚本（只跑验收命令） |
| **清单节点（子 agent A）** | 产出《生物仿真Mx实施清单.md》：Pass 标准 P1..Pn（可测、带阈值）、步骤拆分、交接点确认、风险与备用方案、时间分配 | 不实施代码 |
| **执行节点（子 agent B，可多个并行）** | 严格按已验收的清单实施：写实现、写测试、写验证脚本、跑验证、产出报告与图表；把踩坑与参数定稿写回清单/环境笔记 | 不修改已冻结基线（可增不可破）、不跳过清单步骤、不自行扩大范围 |

> 每个里程碑的 Pass 判定权**只在主 agent**：执行节点自报"完成"不算数，必须主 agent 复跑并核对后才能验收。

## 三、每个里程碑的标准循环（6 步）

### Step 0 · 交接确认（主 agent）
- 读上一里程碑报告 §"Mx 交接"（如 `m2_report.md` §11 → M3 入口），确认交接点（复用哪些类/接口、验证目标、复现入口）。
- 跑基线回归：`pytest neural_exploration/tests` 必须全绿（上一里程碑冻结件不回归）。

### Step 1 · 清单产出（子 agent A：规划节点）
- 输入给 A 的启动指令（固定模板）：
  - 设计文档对应章节（Mx 的内容/Pass/反证路径）+ Lx 层验证标准；
  - 上一里程碑报告交接章节；
  - 本仓库惯例：`docs/生物仿真M0/M1/M2实施清单.md` 的结构（§0 目标与 Pass 标准 → 前置交接 → 规格 → 参考解 → 实现 → 逐项验证 → 回归报告 → 风险 → 时间分配 → 下一里程碑交接）；
  - SESSION_CONTEXT §四 技术踩坑清单（执行节点必读）。
- 产出：`docs/生物仿真Mx实施清单.md`。**Pass 标准必须可测**（数值阈值/统计检验/文件存在性），禁止"看起来合理"类模糊标准。

### Step 2 · 清单评审（主 agent）
- 逐条核对：P1..Pn 是否可测；交接点是否正确（复用已有类而非重写）；是否违反铁律（跳层、为精细而精细、把概率上升到推理层）；风险与备用方案是否覆盖上一里程碑踩坑模式。
- 评审不过 → 打回子 agent A 修订（send_message）；通过 → 冻结清单，进入 Step 3。

### Step 3 · 实施（子 agent B：执行节点）
- 按清单顺序实施；每个验证项产出图表与数据文件到 `reports/neuro/` 与 `data/`；
- 测试全绿（新测试并入 `tests/neuro/`，不得破坏旧测试）；
- 产出 `docs/mx_report.md`（Pass 对照表 + 参数定稿 + 踩坑记录 + Mx+1 交接）+ `reports/neuro/mx_validation_summary.json`；
- 复杂里程碑（如 M5/M9/M12）可由主 agent 拆成多个执行节点并行：如「实现节点」「验证节点」「报告节点」，主 agent 负责合并与总验收。

### Step 4 · 验收（主 agent，唯一裁决者）
验收命令固定为：
1. `pytest neural_exploration/tests -q` → 全绿（新 + 旧全量）；
2. 跑验证入口（如 `python -m neural_exploration.tools.run_mx_validation`）→ 核对每个 Pass 项的输出；
3. 人工抽查产物真实性：报告引用的 png/csv/npz/json 确实存在、尺寸非空、时间戳是本次会话（防伪造）；
4. 对照清单 P1..Pn 逐项打勾，任何一项不过 → **不打回执行节点"再试一次"而是启动反证路径**：记录缺什么/证据指向哪里/下一步假设（设计文档"失败即反证"铁律），产出反证笔记后经用户决策再决定修复或降级；
5. 通过 → 更新 `docs/mx_report.md` 状态为"验收通过"。

### Step 5 · 提交与交接（主 agent）
- git 提交（沿惯例：`feat(Mx): <主题>——P1-Pn 全部达标（验收通过）`），推送 origin/main；
- 更新 `SESSION_CONTEXT.md`（里程碑表状态、当前待办、新踩坑入必读清单）；
- 从报告 §"Mx+1 交接"提取下一里程碑启动输入 → 回到 Step 0。

## 四、验收标准模板（每里程碑 Pass 判定的操作定义）

| 判定项 | 操作定义 |
|---|---|
| 生理/行为 Pass | 对照设计文档该层验证标准：数值阈值（如波形 <5%/10%）或统计检验（p>0.05 / 命中率 ≥70%）由验证脚本自动输出判定 |
| 回归 Pass | `pytest neural_exploration/tests` 全绿（含全部历史里程碑测试） |
| 产物 Pass | 报告引用的每个图/数据/汇总 JSON 存在且非空；验证汇总 JSON 中每个 Pass 项为 true |
| 真实性 Pass | 产物文件 mtime 落在本次执行窗口；数值与报告一致（主 agent 抽查） |
| 交接 Pass | 报告含 "Mx+1 交接" 章节：复用接口、验证目标、复现入口 |

> 主 agent 验收结论三态：**✅ 通过**（进入下一里程碑）/ **❌ 反证**（启动反证路径，记录缺失机制清单）/ **↩️ 打回**（仅限清单/报告文档不完整，不含"没达标"，没达标必须走反证路径）。

## 五、调度规则（主 agent）

1. **串行为主**：阶段一 M3→M7 严格串行（逐层验证铁律）；阶段二 M8/M10 可并行（两轨独立验证体系），M9 依赖 M8、M11 依赖 M10；阶段三 M17 与 M16 并行。
2. **并行度**：同一里程碑内部可拆多个执行节点并行（实现/验证/报告），合并与验收归主 agent。
3. **反证优先**：任何 Pass 失败 → 先记录反证结论（缺失机制清单），再决定修复方向；绝不静默重试。
4. **冻结基线不可破坏**：执行节点只增不改（新增文件/新增参数），改动已冻结文件必须注明并经过回归。
5. **上下文预算**：主 agent 不读执行细节长输出；每里程碑结束，主 agent 只保留报告摘要 + SESSION_CONTEXT 指针，细节留在 docs/ 与 reports/。
