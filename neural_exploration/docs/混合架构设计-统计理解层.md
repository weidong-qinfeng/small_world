# 混合架构设计：统计理解层 + 符号推理层（路线 B）

> 版本：v0.1（方案设计稿，未动代码）
> 目标：让数字大脑"像人一样听懂应用题"，同时保持数学精确、可解释、本地可跑。
> 核心思路：**统计模型负责"听懂"（口语 → 结构化语义），符号引擎负责"算对"（精确推理）。**
> 对应结论：纯符号派"修不完"的根源是枚举型理解；统计学习从数据中归纳规则，原理上补上这一环。

---

## 一、问题定位：为什么纯符号派修不完

当前架构（M1/M2/M3）把"理解"实现为：
```
token 序列 → 规则标签器（SRL）→ 事件状态机（FSM）→ DAG → 精确算法
```
其中**规则标签器和 FSM 全部是手工枚举**。自然语言是组合爆炸的：

| 现象 | 符号派需要的处理 | 实际数量级 |
|---|---|---|
| 省略（给谁？） | 每条省略规则 | 每句式 × 每论元 |
| 指代（她→谁） | 每类指代规则 | 与人物数、距离、角色组合爆炸 |
| 语序变体 | 每种词序模板 | n! 量级 |
| 同义替换 | 每个近义词 | 词汇量级 |
| 歧义消解 | 每条优先级规则 | 无穷 |

**结论：知识包能买来"见过的句式"，买不来"理解新句式的能力"。** 这不是努力问题，是机制问题。

---

## 二、设计原则（混合 = 各取所长）

| 能力 | 符号引擎（现状） | 统计模型（新增） | 混合后 |
|---|---|---|---|
| 口语鲁棒（省略/指代/语序/噪声/同义） | 弱 | **强**（从数据学） | 强 |
| 数学精确（7+6=13 绝不错） | **强**（精确算法） | 弱（会幻觉） | 强 |
| 可解释（推理链每步可审计） | **强**（DAG 透明） | 弱（黑盒标签器） | 推理链仍可解释 |
| 新题材迁移 | 无 | **中**（同分布泛化） | 中 |
| 本地运行 / 隐私 | **强**（CPU/纯本地） | 可选（小模型 CPU 可跑） | 强（选小模型时） |

**分工边界（唯一原则）：**
- 统计层只做一件事：`自然语言 → 结构化事件帧（IR）`
- 符号层只做一件事：`IR → DAG → 精确计算 → 可解释答案`
- 统计层永远不算数，符号层永远不猜词。

## 三、总体架构

```
┌────────────────────────────────────────────────────────────┐
│                        用户输入（任意口语）                    │
└──────────────────────────┬─────────────────────────────────┘
                           ▼
┌────────────────────────────────────────────────────────────┐
│  ① 理解层（统计模型，可替换）                                  │
│     Tier1: 本地小模型（推荐）  Tier2: 7B 微调  Tier3: LLM API │
│     输入: raw_text + token 序列                               │
│     输出: 事件帧列表（IR JSON，含置信度）                       │
└──────────────────────────┬─────────────────────────────────┘
                           ▼  IR（中间表示，见 §四）
┌────────────────────────────────────────────────────────────┐
│  ② 校验层（规则，新增）                                       │
│     - 帧合法性校验（角色/数量/类型一致性）                      │
│     - 低置信度 → 符号兜底 or 拒绝回答（绝不猜）                 │
└──────────────────────────┬─────────────────────────────────┘
                           ▼
┌────────────────────────────────────────────────────────────┐
│  ③ 推理层（符号引擎，保留现状）                                 │
│     事件帧 → DAGBuilder/EventFSM → DAGExecutor → 精确算法      │
│     WorkingMemory 语义栈 / 代词消解 / adding / subtracting    │
└──────────────────────────┬─────────────────────────────────┘
                           ▼
                     可解释答案 + 推理链
```

**关键：① 可整体替换，②③ 不动。** 理解层从"规则"换成"统计模型"，推理层零改动——这就是接口隔离的价值。

## 四、核心：中间表示（IR）契约

理解层与推理层之间只通过 IR 通信。IR 设计为**事件帧列表 + 提问帧**：

```json
{
  "events": [
    {
      "type": "POSSESSION",
      "agent": "小明",
      "theme": "故事书",
      "quantity": 4,
      "confidence": 0.97
    },
    {
      "type": "ACQUISITION",
      "giver": "妈妈",
      "recipient": null,          // 省略 → null，由推理层语用补全
      "theme": "故事书",
      "quantity": 3,
      "confidence": 0.90
    }
  ],
  "query": {
    "type": "QUERY_TOTAL",
    "subject": "小明",
    "theme": "故事书",
    "confidence": 0.98
  }
}
```

**事件类型表（v1，与现有 FSM 一致，可扩展）：**

| type | 语义 | 字段 | 示例 |
|---|---|---|---|
| POSSESSION | 拥有陈述 | agent, theme, quantity | 小明有4本故事书 |
| ACQUISITION | 获取 | giver, recipient, theme, quantity | 妈妈又给他买了3本 |
| LOSS | 失去 | agent, theme, quantity | 弟弟又借走了1本 |
| QUERY_TOTAL | 问总量 | subject, theme | 现在小明总共有几本？ |
| （未来）QUERY_DIFF / COMPARE / MULTIPLY | … | … | M5 扩展 |

**IR 设计原则：**
1. **字段语义化，不携带词序**——语序自由由统计层消化，推理层只见语义。
2. **省略字段 = null**——交给推理层的语用补全（语义栈），统计层不猜。
3. **每帧带 confidence**——校验层据此决策。
4. **类型表可扩展**——新增题型只加 type，不改接口。

## 五、理解层选型（3 个 Tier，推荐 Tier 1）

### Tier 0（现状，纯规则）—— 保留为兜底
- 现有 SemanticLabeler + EventFSM
- 用途：无模型环境、验证集对照、低置信度回退

### Tier 1（推荐）：本地小模型做"句子 → 事件帧"（真正落地的混合）
- **模型形态 A（首选）**：序列标注。中文预训练编码器（如 `bert-base-chinese`，110M 参数）做**语义角色标注**：每个 token 打 `B-AGENT / I-THEME / B-QUANTITY / VERB / Q …` 标签，后接现有 FSM 组装事件帧。轻量、CPU 可推理（~0.2–1s/句）、内存 <1GB、完全本地。
- **模型形态 B（备选）**：小 seq2seq（如 `mT5-small`/`Qwen-0.5B` 微调）直接输出事件帧 JSON。更灵活（可直接出帧），但 CPU 推理慢、显存需求更高。
- 训练：LoRA/全参微调，单卡（如 4090/租用）数小时～1 天。
- **哲学契合**：依然是"能力是学来的"，只是从"人教规则"变成"从数据学"。

### Tier 2（可选增强）：本地 7B 微调
- 如 `Qwen2.5-7B-Instruct` + LoRA，微调成"应用题事件抽取器"。
- 口语鲁棒性显著强于 110M 模型（更懂省略/指代/复杂句式），但需要 ~6GB 显存或量化后 ~4–6GB 内存，CPU 推理 2–10s/句。
- 适用：口语变体测试集正确率要求 > 95% 时。

### Tier 3（可选，若接受联网）：LLM API
- 用 API 做事件抽取（prompt + few-shot 输出 IR JSON）。
- 零训练、鲁棒性最强，但违背"100% 本地"哲学，且每次推理有成本/延迟。
- 建议仅作为**离线增强**（生成训练数据）或可选开关，不作为默认路径。

**推荐路径：先 Tier 1-A（序列标注，本地）落地混合架构，跑通闭环；口语覆盖不足再升级 Tier 2。**

## 六、数据策略：符号层当老师（合成数据生成）

统计模型需要标注语料。**最优雅的来源：让现有符号引擎当老师。**

### 6.1 三路数据源
1. **知识包既有样本**：`pattern_samples` / `tokenizer_examples`（少量，几十条）——种子。
2. **程序化变体生成（主力）**：写一个"口语化生成器"，对每个标准句式随机施加：
   - 省略论元（去接受者/去主语/去宾语）
   - 语序打乱（合法子集）
   - 插入噪声（请问/那个/嗯/呀/帮我算一下）
   - 同义替换（给→送→递；一共→总共→合计）
   - 代词化（小明→他，小红→她）
   - 数字/量词变体
   生成 `(口语, IR)` 对，自动打标签。**量级：每句式生成数千条，总量万级。**
3. **人工校正集**：从生成集抽样 200–500 条人工校对，作为测试集（防"老师教错"）。

### 6.2 为什么可信
- 标签（IR）由确定性规则生成，无标注噪声（比人工标注一致性好）。
- 符号引擎已知的语序/省略/噪声变体正是统计层要学的；统计层学会后比老师**更鲁棒**（它能泛化到老师没枚举的组合）。

### 6.3 数据闭环（M5 自学习铺垫）
- 用户点"答案对吗 y/n" → 错例进入增量训练集 → 周期性重训/增量微调。
- 这是从"死记"到"越用越聪明"的真正路径（不是加 pattern，而是加样本）。

## 七、推理层改造点（现状保留，只做两处小改）

| 组件 | 处置 | 说明 |
|---|---|---|
| DAGGraph / DAGNode / DAGExecutor | **不动** | 原子操作虚拟机，与理解层无关 |
| 算法注册表（adding/subtracting…） | **不动** | 精确计算 |
| WorkingMemory（语义栈/代词消解） | **不动** | 语用补全仍在符号层 |
| ReasoningArea.run | 小改 | 入口分流：统计 IR → 校验 → 推理；无模型/低置信度 → 现 SRL/PatternMatcher 兜底 |
| EventFSM | 保留 | 作为"IR 组装器"（统计标签 → 帧）和纯规则兜底双角色 |
| SemanticLabeler | 保留为兜底 | 统计模型不可用时回退 |

**核心原则：理解层可整体拔插，推理层零改动。**

## 八、置信度、回退与拒绝策略（绝不猜）

```
统计层输出帧置信度 c
├─ c ≥ 0.9        → 直接进入符号推理
├─ 0.6 ≤ c < 0.9  → 符号层二次校验（帧合法性 + 与语义栈一致性）；
│                    校验通过 → 推理；不通过 → 回退 Tier0 规则
├─ 0.3 ≤ c < 0.6  → 回退 Tier0 规则；Tier0 也失败 → 拒绝并说明
└─ c < 0.3        → 拒绝回答："我没听懂，能换个说法吗？"（不猜）
```

**拒绝也是能力**：当前系统答错（如"妈妈又给3本"→把妈妈当接受者）是因为没有置信度概念、没有拒绝机制。统计层天然给概率，正好补上"不知道就直说"。

## 九、实施路线图（4 个 Phase，每个独立可交付）

### Phase 0：IR 契约落地（0.5 天，纯代码）
- 定义 IR Pydantic 模型（EventFrame / QueryFrame / ParseResult）
- EventFSM 改造：`规则组块 → IR 帧`（现有逻辑包一层，输出即 IR）
- 交付验证：M1/M2/M3 全过 + 输出可序列化为 IR JSON（零行为变化）

### Phase 1：数据生成器 + 老师闭环（1–2 天）
- 写 `data_gen.py`：标准句式 → 口语变体 + IR 标签（§6.1 的 3 路源）
- 生成训练集（万级）+ 人工校正测试集（200–500 条）
- 交付验证：生成器随机抽查正确率 100%（确定性规则自检）

### Phase 2：Tier1 序列标注模型（2–4 天 + 训练）
- 数据 → `bert-base-chinese` 序列标注（BIO 标签：AGENT/THEME/QUANTITY/VERB/Q…）
- 推理：`onnxruntime` 量化，CPU 可跑
- 接入：`ReasoningArea.run` 分流（统计 → 校验 → 推理；兜底保留）
- 交付验证：**口语化测试集正确率 ≥ 90%**（重点：省略/指代/噪声/语序）+ M1/M2/M3 零回归 + 117 tests 全过

### Phase 3：置信度/回退/拒绝上线（1 天）
- 帧置信度接入 §八 策略
- 新增"拒绝回答"路径与测试
- 交付验证：人为制造歧义句 → 正确拒绝而非答错；正常题零回归

### Phase 4（可选）：升级 Tier2 7B 微调 或 数据闭环（M5 自学习）
- 口语覆盖率不足 → Tier2 微调
- 用户反馈 y/n → 增量训练集 → 重训（真正"越用越聪明"）

## 十、成本估算

| 项 | Tier1（推荐） | Tier2（可选） | Tier3（API） |
|---|---|---|---|
| 训练 | 单卡 GPU 数小时–1天（可租云 ~¥50–200） | 1–2 天（¥200–500） | 无 |
| 推理硬件 | CPU 可跑，内存 <1GB | 量化后 4–6GB 内存 | 需联网 |
| 每句推理 | ~0.2–1s（CPU） | 2–10s（CPU） | ~1–3s + 网络 |
| 隐私 | 100% 本地 | 100% 本地 | 数据出本地 |
| 哲学契合 | ✅ 能力学来的 | ✅ | ⚠️ 依赖外部 |

**推荐：Tier1-A 序列标注落地（低成本、本地、够用），预留 Tier2 升级接口。**

---

## 十一、风险与缓解

| 风险 | 缓解 |
|---|---|
| 统计层把"听懂"做成了新黑盒 | 输出是 IR 帧（结构化），推理链仍 100% 可解释；黑盒只限于"分词→标签" |
| 训练数据被符号老师"教错" | 合成数据确定性生成 + 人工校正测试集 + 置信度拒绝 |
| 小模型口语鲁棒性不够 | 预留 Tier2 升级；Tier0 规则兜底 |
| 生成器本身枚举有限 | 生成器持续扩充（同义/句式模板可插拔）；错例反馈闭环 |
| 数学错误（模型幻觉算错） | 模型永不参与计算——计算 100% 在符号层（这是混合架构的安全网） |

```
口语化测试集（新，统计层评估）：
  L1 省略：省略接受者/宾语/主语  各 50 题
  L2 指代：他/她/它/他们 + 多人物  各 50 题

  口语集 ≥90% + 符号集 100% + 任何 commit 必须双绿
```
