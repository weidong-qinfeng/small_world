## 1. 独立解码与三件自证

### 1.1 解码路径（本节点独立写就）

```
20 B 大端头 `>5I` = (ndim=4, 200, 200, 1, 10)
 → `gzip.decompress(raw[20:])` → 800,000 B
 → `>i2` → reshape(200,200,1,10, order='F') → [:, :, 0, :] → (200,200,10)
```

- 头字段实测 **`(4, 200, 200, 1, 10)`**，**与小端对照 `(67108864, 3355443200, …)` 完全不同** ⇒ 大端确认；
- 解压后 **800,000 B = 400,000 × int16** ✓ 与头声明的形状一致；
- **源元数据佐证**（`data/m11_raw/microns/series_s4s7f4_attributes.json`）：
  `axes=[x,y,z,t]`、`blockSize=[200,200,1,10]`、`dataType=int16`、`dimensions=[248,440,1,40000]`、`resolution=[2.5,2.5,10,0.15873]`
  ⇒ 该 series 全时间轴 = **40,000 帧 @0.15873 s ≈ 6,349 s**，我方持有其中 **2,000 帧（5%）**。

### 1.2 🔴 自证之前先拦下**本节点自己的两处口径错**（同一家族：字节序 / 轴序）

| # | 缺陷 | 实测症状 | 如何被拦下 | 修复 |
|---|---|---|---|---|
| **E1** | **无符号读法的字节序** | 把 `mat.view(">u2")` 用在**已 `astype(np.int16)`（本机小端）**的数组上 ⇒ 又交换一次字节 ⇒ 哨兵计数 **622,888**（真值 10,383，**60×**） | 与"合格值域"对账：`uint16>65000` 应 ≤ 负值数，622,888 > 10,383 ⇒ 自相矛盾 | 改 `mat.view(np.uint16)`（本机序），并加"等价性充分条件"打印 |

### 1.4 ② 哨兵掩膜（**独立复算**，并精确化判据）

- `int16 < 0`：**10,383 / 80,000,000 = 0.012979%** —— **与 M11-B1 的 10,383 / 0.01298% 逐位一致** ✓
- 同字节序 `uint16 > 65000`：**10,383** ⇒ 两判据在**本数据集上完全重合（差 0）**
- **但两式恒等不成立**（须写明，避免当恒等式用）：
  `int16<0` ⇔ 高位为 1 ⇒ 域 **[−32768, −1]**；`uint16>65000` ⇔ `int16 ∈ [−535, −1]`（**前者子集**）。
  **等价性的充分条件 = 全体负值 ≥ −535**；实测全局 `min = −138` **⇒ 该条件成立**，故本次重合。
- 独立复算的其余一致性：`vmin = −138` ✓（与 B1 相同）；逐对象 `p50` 区间 **[1212, 2797]** ✓（与 B1 完全相同）。

### 5.2 未定位项（如实登记，**不代填**）
